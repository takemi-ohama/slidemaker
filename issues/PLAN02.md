# 改修計画: Gemini 3 Pro Image への完全適応と座標系のピクセル化

## 背景
現状のSlidemakerは、LLMに対して座標をパーセンテージ（0-100%）で出力させているが、Gemini 3 Pro Imageのような高解像度ビジョンモデルを使用する場合、パーセンテージ変換による誤差や、フォントサイズの過大評価が発生している。また、画像の切り出し範囲が不正確で、図表が見切れる問題も残っている。

ユーザー指示 (`issues/i08.md`) に基づき、処理全体をピクセルベース（またはEMU換算可能な固定座標系）に移行し、LLMに正確なサイズ情報を渡して推論させることで精度を向上させる。

## 方針
EMU単位（例: 幅9,144,000）は数値が巨大すぎてLLMが扱いづらいため、PowerPointの96 DPI基準である **ピクセル単位 (16:9の場合 960x540)** をLLMとの通信における基本単位とする。内部処理ではこれをEMUに変換してPPTX生成を行う。

## 実装ステップ

### 1. データモデルの更新 (`src/slidemaker/image_processing/phase_models.py`)
*   `RoughPosition`, `RoughSize`, `PrecisePosition`, `PreciseSize` のバリデーションルールを変更。
    *   `le=100` (100%以下) という制約を削除。
    *   代わりに `ge=0` (0以上) のみを維持し、スライドサイズ（例: 960, 540）までの値を許容する。

### 2. プロンプトの刷新 (`src/slidemaker/llm/prompts/image_processing.py`)
*   システムプロンプトおよびユーザープロンプトを大幅に書き換える。
*   **指示内容**:
    *   「この画像は 幅{width} px, 高さ{height} px です」と明示。
    *   座標出力は「ピクセル単位」で行うよう指示 (例: `x: 100, y: 200, width: 300, height: 50`).
    *   フォントサイズはピクセル高さ、またはポイント数 (`pt`) で直接推定させる。
        *   ヒントとして「高さ540pxにおける12ptは約16px」といった基準値を提示する。
    *   **画像のバウンディングボックス**:
        *   「ラベルやキャプションを含む完全な領域」を特定するよう強調。
        *   マージンを含めた座標を出力させる。

### 3. アナライザーロジックの修正 (`src/slidemaker/image_processing/analyzer.py` 等)
*   `ImageAnalyzer`:
    *   パーセンテージからピクセルへの変換ロジック (`_percentage_to_pixels_position` 等) を削除またはバイパス。
    *   LLMからの出力をそのままピクセル座標として扱う。
*   各フェーズ (`phases/*.py`):
    *   プロンプトに動的にスライドサイズ（960x540など）を埋め込む。

### 4. フォントサイズ推定のロジック変更 (`src/slidemaker/image_processing/phases/style_estimator.py`)
*   これまでの「高さ% × 係数」による計算を廃止。
*   LLMが返した `font_size` (pt) を信頼するか、または `bounding_box_height` (px) からより直接的な計算式で算出する。
    *   計算式案: `font_size_pt = element_height_px * 0.75` (行間考慮) ではなく、文字そのものの高さをLLMに推定させる方が良いかもしれないが、まずはLLMに `pt` で出させてみる。

### 5. PDF読み込みとリサイズの確認 (`src/slidemaker/image_processing/loader.py`)
*   既に960x540への正規化が入っているため、これを維持・徹底する。
*   PDFのアスペクト比が4:3の場合は `720x540` にするなど、アスペクト比に応じたキャンバスサイズ決定ロジックを確認（現状は16:9固定の傾向があるため、柔軟性を持たせる）。

## 期待される効果
*   座標精度の向上: `%` 計算による丸め誤差がなくなる。
*   フォントサイズの適正化: 具体的なピクセル基準で推論するため、"Huge" なのか "Normal" なのかの判断基準が明確になる。
*   画像切れの解消: ピクセル単位で「ここからここまで」と指定させることで、曖昧さを排除する。
