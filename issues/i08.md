# 開発AIエージェント向け指示書

* このドキュメントは開発AIエージェント向けの指示書です。
* チャットで「docs/cmd01.mdのx番を実行してください」と言われたらこのファイルを読み、見出しに書いてある番号の内容を実行してください。

# 1. サンプルを使った動作検証
* cliを使ってsamples/MDX_Strategic_Engine_2026.pdf をpptxに変換してください
* powerpoint mcpを使って出来上がったpptxを確認し、MDX_Strategic_Engine_2026.pdfが再現できているかどうかを確認してください
* 問題を把握し、コードを修正してpptxを修正して確認する工程を、問題がなくなるまで繰り返してください

# 2. gemini3-pro-imageへの適応
* llmにgemini3-pro-imageを採用することによってだいぶ良くなりましたが、まだ問題があります。
    * フォントサイズの推定を頻繁に間違える
    * 画像のトリミングを間違える(絵が切れる)
* 以下のようにコードやプロンプトを改修して精度を上げてください
* pdfファイルのページ縦横比を判定する(python)
* powerpointのサイズに合うように1ページのpngファイルのサイズを決定する
* サイズ情報に基づいてPDFを1ページ=1pngに変換する(python)
    * 以降、リサイズ処理は行わなくて済むようにすること
    * pptxはこの縦横比とサイズ情報に合わせて新規作成する
    * EMU単位に変換し、以降EMU単位系で情報のやり取りを行う
* llmにこのサイズ情報を伝え、EMU単位で計測・計算するように指示を出す
* llmを使って大まかなページレイアウトをEMU単位で座標(x,y,x0,y0)で特定する
* EMU単位で各画像ブロック要素、文字ブロック要素の座標とz軸を特定する(llm)
* EMU単位で各文字ブロックのフォントサイズを特定する(llm)
* 文字情報を読み取る(llm)
    * 文字に塗りつぶしや文字色、影などがあればそれらも読み取る
    * powerpointで書式設定可能な項目はできるだけ再現できるようにする
    * フォント種別やEMU単位でのフォントサイズを特定する
    * 枠線はz軸の異なる画像として処理する
    * 画像と一体化している文字は無理に文字を抽出せず画像ブロック要素として扱う
* 画像ブロック要素の切り出しを行う(llm)
    * 背景は可能な限り塗りつぶした上で透過させる
* 背景色または背景画像を抽出する(llm)
    * 背景色はグラデーションなども考慮すること
    * 背景画像が存在する場合、要素が載っていて隠れている箇所は補完する
* powerpointを新規作成し、EMU単位で画像と文字を配置する
* 背景の設定、文字ブロック要素のフォント設定、書式設定を行う
* z軸を調整する
* 以上をページ分繰り返してpptxを保存する
* 改修計画をissues/PLAN02.mdに出力する
    * ただし、この構想はラフであり、既存実装や別の方法の方が妥当であればそちに従うこと

# 3. 自動精度向上
* .serena/memories/pdf-pptx-conversion-validation-workflow.md に記載された精度改善フローを繰り返し実行してください。
* 目標はPDFとpptxの完全一致です(ただし文字は文字として編集できる状態であること)
* 対象pdfは samples/MDX_Strategic_Engine_2026.pdfです。
    * 全ページを対象にすると重いので、samples/MDX_Strategic_Engine_2026_pages1-3.pdfのように切り出してフローを回します。
    * samples/MDX_Strategic_Engine_2026_pages1-3.pdf が完全に一致したら、次の3ページを切り出したpdfを作ってフローを回します。
* レポートやチャットへの出力はすべて日本語で。また毎回日本時間で応答日時を出力してください。
* ユーザは数時間不在になりますので、ユーザの指示があるまでフローをループし続けて改善を続けてください。
    * ユーザに質問が発生しても、自身で解決して先に進めてください。
