## 問題概要

PDF→PPTX変換（`test_96dpi.pptx`生成）において、2つの問題が報告されています：

1. **画像要素のトリミングが成功していない**

   → **診断結果**: LLMの座標推定エラーが原因

**調査結果**:

**問題の特定**:

1. **テキストブロック#5（3つめのコンテンツ）が誤配置**
   - 実際: `left=9.97%`（左端、1つめの柱の下）
   - 期待: `left≈65%`（右端、3つめの柱の下）

2. **テキストブロック#7のY座標がやや低い**
   - 実際: `top=62.99%`
   - 期待: `top≈59%`（#5, #6と同じ高さ）

**原因**:
LLMの画像分析時の座標推定エラー。視覚的に3列のレイアウトを正しく認識できていない可能性。

## 根本原因の分析

### LLMプロンプトの問題点

**現在のプロンプト**: `src/slidemaker/llm/prompts/image_processing.py`

```python
IMAGE_ANALYSIS_SYSTEM_PROMPT = """You are an expert in analyzing presentation slides and images.
Your task is to identify and locate text and image elements within slides, and output the results as STRICTLY VALID JSON.

=== STEP 2: MEASURE POSITIONS AND SIZES ===

For each element you identify:
- Measure its position (x, y) as PERCENTAGES (0-100) from the top-left corner
- Measure its size (width, height) as PERCENTAGES (0-100) of the slide dimensions
- x: 0 = left edge, 100 = right edge
- y: 0 = top edge, 100 = bottom edge
...
"""
```

**問題点**:
- 境界制約（Boundary Constraints）は詳細に記載されている
- しかし、**複数列レイアウト（3列構成など）の認識ガイドライン**が不足
- テキストブロックが視覚的にグループ化されている場合の処理方法が不明確

### 座標正規化処理の確認

**座標変換フロー**:

1. **LLM出力**: パーセンテージ座標（0-100%）
2. **`ImageAnalyzer._normalize_position`**: パーセンテージ → ピクセル座標変換
   ```python
   # src/slidemaker/image_processing/analyzer.py
   def _normalize_position(self, position_dict: dict, image_size: tuple[int, int]) -> Position:
       x_pct = position_dict.get("x", 0)
       y_pct = position_dict.get("y", 0)
       x_px = int((x_pct / 100) * image_size[0])  # パーセンテージ → ピクセル
       y_px = int((y_pct / 100) * image_size[1])
       return Position(x=x_px, y=y_px)
   ```
3. **`ConversionWorkflow._process_images`**: ピクセル座標 → PowerPoint EMU座標変換

**正規化処理は正常に動作**しているため、問題はLLMの座標推定段階にある。

## 修正方針

### 方針1: LLMプロンプトの改善（推奨）✅

**目的**: LLMに複数列レイアウトの認識ガイドラインを追加

**修正箇所**: `src/slidemaker/llm/prompts/image_processing.py`

**追加内容**:

```markdown
=== LAYOUT PATTERN RECOGNITION ===

**Multi-Column Layouts (2-3 columns):**
- Identify if the slide uses a multi-column layout (common in comparison slides, feature lists)
- For 3-column layouts:
  - Column 1: x ≈ 10%, width ≈ 25-30%
  - Column 2: x ≈ 37-40%, width ≈ 25-30%
  - Column 3: x ≈ 65-67%, width ≈ 25-30%
- Text blocks directly below column headers should:
  - Align horizontally with their respective column
  - Start at similar Y coordinates (within 2-3% tolerance)

**Visual Grouping:**
- If text blocks are visually aligned in columns, preserve that alignment
- Headers + descriptions in the same column should have consistent X coordinates
```

**期待される効果**:
- LLMが3列レイアウトを認識し、正しいX座標を推定
- テキストブロック#5が`left≈65%`に配置される
- テキストブロック#7のY座標も改善される

---

### 方針2: 座標検証・補正ロジックの追加（オプション）⚠️

**目的**: LLM出力後に座標の妥当性を検証し、明らかな誤りを自動補正

**修正箇所**: `src/slidemaker/image_processing/analyzer.py`

**メリット**:
- LLMプロンプトに依存せず、後処理で補正できる
- 複雑なレイアウトにも対応可能

## 補足: 画像トリミング問題の誤認識について

**なぜ「画像トリミングが成功していない」と誤認識されたか？**

1. **視覚的な確認不足**
   - PowerPointファイルを開いて画像を確認していなかった
   - コード上の`padding_ratio`のみを見て判断

2. **用語の混乱**
   - 「トリミング」= 画像の切り出し処理そのもの
   - 実際には正常に動作しているが、「トリミング位置が微妙にずれている」と誤解された可能性

3. **座標問題との混同**
   - テキストブロックの座標問題と画像トリミング問題を混同

**結論**:
- 画像トリミングは**正常に動作している**
- `padding_ratio = 0.20`（20%）は適切で、**変更不要**
- 今後は視覚的確認を優先する
